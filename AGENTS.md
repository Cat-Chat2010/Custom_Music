# AGENTS.md — Пам'ять та інструкції проєкту Custom_Music

Цей файл є постійною пам'яттю агента (Antigravity memory). Усі зазначені правила, вимоги та архітектурні рішення є обов'язковими для дотримання в усіх наступних сесіях та запитах.

---

## 1. Загальна інформація про проєкт
- **Назва мода:** `Custom_Music` (ім'я архіву: `custom_music-X.Y.Z-NeoForge.jar`)
- **Mod ID:** `custommusic`
- **Платформа:** Minecraft Java Edition `1.21.1`
- **Завантажувач:** `NeoForge 21.1.65` (Java 21)
- **Тип:** Client-Only (виключно клієнтський мод)
- **Репозиторій GitHub:** `Cat-Chat2010/Custom_Music` (гілка `main`)

## 2. Правила версіонування та Git (СУВОРО)
1. **Збереження в Git:**
   - Зберігати в Git (коміти, пуші) **ТІЛЬКИ коли про це прямо просить користувач**. Не комітити і не пушити автоматично без запиту!
2. **Формат версій (`X.Y.Z_NeoForge`):**
   - **Перша (`X`) та друга (`Y`) цифри** версії змінюються **тільки коли користувач прямо про це попросить**.
   - **Третя цифра (`Z`)** збільшується на +1 з кожним новим збереженням/завантаженням на Git (наприклад, `0.0.4` -> `0.0.5` -> `0.0.6`).
   - У `gradle.properties`: `mod_version=X.Y.Z-NeoForge`.
3. **Коміти, релізи та файли (ОБОВ'ЯЗКОВО кожного разу):**
   - **Обов'язкове створення GitHub Release:** кожного разу, коли користувач просить зберегти в Git, обов'язково публікувати повноцінний реліз на GitHub (через API/скрипт) з відповідним тегом `X.Y.Z_NeoForge`.
   - **Двомовний опис релізу (СУВОРО):** в описі кожного релізу текст пишеться **СПОЧАТКУ англійською мовою**, а потім **те ж саме українською мовою**.
   - **Структура релізу (як у модах, чітко за категоріями):**
     - Зрозуміла назва релізу (наприклад: `Custom_Music 0.2.0: Native MP3 Support & Single Folder` / `Нативна підтримка MP3 та єдина папка`).
     - Чіткі розділи в описі:
       - Англійська частина: `### Added`, `### Changed`, `### Removed` (або `### Fixed`).
       - Українська частина: `### Додано`, `### Змінено`, `### Видалено` (або `### Виправлено`).
     - Пункти списку з чітким, зрозумілим та структурованим описом.
   - До кожного релізу окремо додавати два файли-асети:
     1. Сам готовий зібраний файл мода (`custom_music-X.Y.Z-NeoForge.jar`).
     2. Зіпку вихідного коду (`custom_music-X.Y.Z-src.zip`).
   - **Увага для PowerShell:** розділяти команди крапкою з комою `;` (не використовувати `&&`).

## 3. Збірка та оточення (Build System)
- Системний Java не завжди встановлений у глобальному PATH, тому використовується JDK 21 лаунчера Minecraft.
- Скрипт збірки: `build_mod.bat` автоматично налаштовує `JAVA_HOME` та запускає `gradlew.bat clean build` (попередньо очищаючи старі збірки).
- Готовий артефакт знаходиться в `build/libs/custom_music-X.Y.Z-NeoForge.jar`.

## 4. Безпека файлів користувача та аудіо-рушій (КРИТИЧНО)
- **Оригінальні файли користувача НІКОЛИ не видаляються і не переміщуються!**
- При виборі через системний провідник файли виключно **копіюються** (`Files.copy`) безпосередньо у папку `custom_music/`.
- Оригінали пісень у користувача (наприклад, у папці «Завантаження» чи на робочому столі) залишаються недоторканими в початковому форматі.
- **Повна відмова від FFmpeg та сторонніх утиліт:** мод використовує чистий Java-декодер (JLayer), вбудований безпосередньо в JAR-файл мода.
- **Підтримка форматів:** `.mp3` та `.ogg` відтворюються нативно через аудіорушій Minecraft (OpenAL) без жодної конвертації на диску.
- **Єдина папка `custom_music/`:** усі треки зберігаються прямо в `.minecraft/custom_music/` без підпапок `tracks/`, `import/` або `ffmpeg/`.
- **Автоматична міграція:** при оновленні мода старі файли з `tracks/` та `import/` автоматично переміщуються у корінь `custom_music/`, а непотрібні старі папки видаляються.
- **Вимоги до інтернету:** підключення до мережі потрібне **тільки при першому запуску** для підтягування залежностей Gradle та NeoForge. Надалі вся робота мода та компіляція повністю офлайн.

## 5. Робота музики та поведінка у грі
1. **Музика в меню та налаштуваннях:**
   - Музика **не повинна зупинятися чи ставитися на паузу** при відкритті налаштувань (`OptionsScreen`, `SoundOptionsScreen`, `CustomMusicScreen`) або меню паузи.
   - Реалізовано через `SoundManagerMixin`: перехоплення `SoundManager.pause()` і миттєве відновлення через `CustomMusicPlayer.getInstance().resume()`.
   - `CustomMusicPlayer.tick()` викликається кожен клієнтський тік (`ClientTickEvent.Post`) незалежно від того, чи відкритий екран інтерфейсу.

2. **Додавання музики прямо з гри:**
   - Натискання кнопки «📁 Додати музику» викликає справжній нативний Windows Explorer File Dialog (`System.Windows.Forms.OpenFileDialog` через PowerShell процес, з AWT як fallback).
   - Підтримка множинного вибору (Ctrl/Shift) файлів `.mp3` та `.ogg`.
   - Кнопку ручної конвертації `🔄` прибрано — обрані треки миттєво додаються до списку і готові до програвання.
   - Процес відкриття асинхронний, щоб вікно гри не зависало.

3. **Спливаюче повідомлення HUD та Міні-плеєр (`NowPlayingHud`):**
   - Розташування: правий верхній кут екрана впритул до меж (без порожніх відступів).
   - Розмір плашки: фіксований, компактний (96x34, зменшено по довжині).
   - Фон: затемнений напівпрозорий, контурна рамка.
   - Ліміт назви: рівно **18 символів** (+ `...`).
   - Елементи всередині плашки:
     1. Зверху назва треку (масштаб 0.65x).
     2. Під назвою смужка прогресу відтворення (білий індикатор).
     3. Зліва над смужкою (під текстом назви): скільки часу пройшло (наприклад `0:42`, шрифт 0.5x).
     4. Справа над смужкою: скільки залишилось із мінусом попереду (наприклад `-2:18`, шрифт 0.5x).
     5. Зліва під смужкою: скільки всього триває пісня тим же шрифтом (наприклад `3:00`, шрифт 0.5x).
   - **Режим постійного міні-плеєра (`Ctrl + O`):**
     - Натискання `Ctrl + O` (без Shift) відкриває віконце і воно **не закривається** саме.
     - Повторне натискання `Ctrl + O` плавно закриває його.
     - При зміні пісні віконце плавно ховається за край (slide out) і виїжджає назад (slide in) вже з новою піснею та оновленим таймлайном.
   - **Звичайний режим:** якщо міні-плеєр не закріплений через `Ctrl + O`, плашка з'являється на 7 секунд при старті нової пісні.

4. **Керування та гарячі клавіші:**
   - Назва розділу в налаштуваннях керування: ім'я мода `Custom_Music`.
   - `Налаштування музики`: комбінація за замовчуванням `Ctrl + P` (без Shift).
   - `Міні-плеєр HUD`: комбінація за замовчуванням `Ctrl + O` (без Shift).

5. **Інтерфейс списку треків (`TrackListWidget`):**
   - Зліва у кожного треку 2 тонкі вертикальні смужки для перетягування (Drag-and-Drop) порядку пісень.
   - Біля назви кнопка `▶` / `⏸` для швидкого попереднього прослуховування або зупинки треку.
   - Праворуч відображається точна тривалість треку (формат `хв:сек`).

6. **Маркування треків та ванільна музика:**
   - Кольорові бейджі в меню налаштувань:
     - `[Custom]` (блакитний `AQUA`) — власні завантажені користувачем треки.
     - `[Vanilla]` (сірий `GRAY`) — фоновий саундтрек гри (Overworld, Nether, End, Creative, Menu).
     - `[Disc]` (золотий `GOLD`) — музичні платівки Minecraft (`Pigstep`, `Cat`, `Otherside`, `Creator` тощо).
   - Повна підтримка всіх 79 офіційних звукових файлів музики Minecraft 1.21.1 з фіксованими реальними шляхами з `17.json`.
   - Точна тривалість для кожного ванільного треку та відтворення без випадкового вибору.
   - Автоматичне очищення застарілих або неіснуючих ключів (наприклад `v_hal1`, `v_chris`) та міграція застарілих назв (`v_echo_in_the_canyon` -> `v_echo_in_the_wind`) у `MusicConfig.syncWithDisk`.
   - Точне авторство треків: `Aaron Cherof - Precipice`, `Aaron Cherof - Featherfall`, `Lena Raine - Endless`.
